# R&C1 representative enemy attack patterns

Authority: retail NTSC-U original, `SCUS-97199`; ISO SHA-256 `ab849fe7cc9cc81c487d61b0d3ea15b5849943481b6a6ebf4d9aa9cf7bc40d9d`; executable SHA-256 `e050581032e4bb3f20341307da5b69b76f1574910519155380ea771e55c3c0c9`.

This note narrows the first reusable enemy-attack boundary. It deliberately does **not** create a generic enemy combat component: the fixed Veldin overlay proves one complete outgoing melee contract for class 749 and a second independently damageable/targeting candidate, class 1440, whose outgoing contact-damage semantics remain unresolved.

The payload-free machine-readable witness is `research/generated/rac1-enemy-attack-patterns.json`, generated by `tools/rac1-enemy-attack-pattern-probe.py`.

## Class 749: recovered melee cadence

Class 749 remains the only loaded Veldin family with a fully recovered outgoing attack path.

Its native state machine uses state 6 for the targeted/pursuit path, state 7 for attack, and state 8 for return-home. Entry to state 7 requires target distance **strictly below 2.0** and facing error **strictly below** raw float `0x3e32b8c2`. Once attacking, the state is retained through distance **1.5 inclusive** and through the same facing threshold; exceeding those boundaries returns to the targeted state.

Native sequence 5 is the attack sequence. The retained animation witness has 21 decoded frames over 102 native updates. Marker `34.0` is crossed at native update 68, emits one attack event there, and naturally repeats every 102 updates while state 7 remains active. The representative damage consequence is native damage `1.0`.

The loaded executable independently pins the marker/emitter chain:

- `0x002d4c74` materializes marker `34.0`;
- `0x002d4c7c` calls the animation-marker test;
- `0x002d4cb4` calls attack emitter `0x002599e8`;
- `0x002d4cb4` is the **only direct caller** of `0x002599e8` in the loaded image.

The attack call also materializes a raw scalar `0x3eaa7efa`, decoded as approximately `0.3330000043`, before entering the shared geometry/damage machinery. That scalar is retained as part of the class-749 call witness, but its semantic dimension is unresolved. It must not be renamed “radius”, “reach”, or another geometry role without a separate recovery of helper `0x002599e8` / `0x002598b0`.

The practical class-749 contract is therefore:

| Property | Recovered value |
|---|---:|
| attack entry distance | `< 2.0` |
| attack retention distance | `<= 1.5` |
| facing threshold | raw `0x3e32b8c2`, strict on entry |
| attack state | `7` |
| native sequence | `5` |
| animation marker | `34.0` |
| first marker update | `68` |
| repeat period while retained | `102` native updates |
| representative native damage | `1.0` |

These are **class-749 script rules**, not engine-wide enemy defaults.

## Class 1440: second damageable/targeting candidate

The same fixed Veldin witness contains nine live class-1440 Mobies. All use update routine `0x002e0b88`; eight are in native state 1 and one is in state 3. Every live PVar has `2.0` at `+0x20`.

Class 1440 independently proves the same broad damage-intake architecture seen in class 749:

- `0x002e16e8` calls common damage lookup `0x0025a420`;
- `0x002e1710` calls common damage consumer `0x0025a478`;
- `0x002e1774` loads PVar `+0x20`;
- `0x002e1784` subtracts returned native damage;
- `0x002e17bc` stores the resulting PVar `+0x20`.

This is an independent second witness that a class script can own its health scalar while using the common native damage-record transport.

PVar `+0x110` is also used as a Moby pointer by the class-1440 script. In the fixed witness six instances point to Ratchet's current class-0 Moby and three are null; none points at another Moby. That makes class 1440 a useful targeting-family candidate, but target identity plus health still does not by itself prove hostility.

### Native state-5 contact query

Class 1440 has a nine-entry state dispatch; state 5 begins at `0x002e11a4`. It constructs a transient descriptor containing:

- source Moby at descriptor `+0x80`;
- `0x00010000` at `+0x84`;
- source native class at `+0x8a`;
- float `1.0` at `+0x8c`;
- integer `1` at `+0x90`.

State 5 performs two calls to the VU-backed query routine `0x001efc70`, at `0x002e1348` and `0x002e13bc`. After a successful query, the script compares the query-owned Moby result with the current player Moby. On that player-contact branch it calls class-local helper `0x002e2040` and drives the native transition toward state 6.

This is concrete contact/query evidence, but **not yet a recovered outgoing damage event**. Within the complete class-1440 update range `0x002e0b88..0x002e1df0` there is no direct call to class-749 attack emitter `0x002599e8` and no direct call to damage constructor `0x00259bc8`. The descriptor's `0x00010000` and `1.0` values resemble known damage records, but resemblance is not enough to name the `1.0` field as damage.

Accordingly this task does not assign class 1440 an attack damage, cadence, range, facing gate, or universal contact geometry.

## Cross-family boundary

The useful shared seam is narrower than “enemy attack behaviour”:

- **proven common:** native Moby state/update dispatch, damage-record lookup/consumption, and class-owned health subtraction after native damage is consumed;
- **class 749 only:** pursuit-to-attack range, facing threshold, attack state/sequence, marker timing, repeat cadence, outgoing emitter call and representative one-damage consequence;
- **class 1440 only:** nine-state dispatch, `2.0` PVar health, player/null PVar `+0x110` Moby pointer population, state-5 two-query contact path and state-6 contact transition;
- **still unresolved across families:** shared melee geometry, shared attack timing, shared outgoing damage scalar, contact damage semantics, and enemy projectile behaviour.

No separately identifiable weapon-like enemy projectile was recovered from the fixed loaded overlay. No projectile child archaeology is emitted from this task.

`py -3.12 tools/rac1-enemy-attack-pattern-probe.py --savestate "<authorized SCUS-97199 Veldin savestate>" --zstd-dll "<zstd.dll>" --out research/generated/rac1-enemy-attack-patterns.json`

The generated JSON contains hashes, addresses, words, counts and derived scalar values only; no retail payload bytes are committed.
